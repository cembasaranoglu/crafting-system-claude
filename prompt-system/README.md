# `prompt-system/` — copy-ready prompts, gates, schemas, and templates

This directory is the prompt layer of [Crafting Kit](../README.md). It contains the prompts, manifests, policies, schemas, templates, and prompt tests that power both standalone Claude/Cursor usage and the Claude Code plugin under [`../plugin/crafting-system/`](../plugin/crafting-system/).

The prompts are designed for **Claude chat, Claude Code, Cursor, and other coding agents**. The pack is strict by default: it separates `fact`, `assumption`, `recommendation`, `unknown`, `blocker`, `not run`, `failed`, `validated`, `not applicable`, and `deferred`.

## How to start

Read [`GUIDE_START_HERE.md`](GUIDE_START_HERE.md), then follow the recommended default flow from [`../README.md`](../README.md):

1. [`prompts/00_claude_base_prompt.md`](prompts/00_claude_base_prompt.md)
2. [`prompts/150_global_risk_gate.md`](prompts/150_global_risk_gate.md)
3. [`prompts/151_intent_stage_router.md`](prompts/151_intent_stage_router.md)
4. [`prompts/153_assumption_ban_contract.md`](prompts/153_assumption_ban_contract.md)
5. The stage prompt for your task — see [`PROMPT_INDEX.md`](PROMPT_INDEX.md)

If side effects are in scope, add `154_execution_control.md`, `155_tool_permission_policy.md`, `156_human_approval_protocol.md`. If credentials are in scope, add `158_secret_and_runtime_credentials.md`. Before claiming validation, add `157_validation_and_reporting_gate.md`.

## Manifests and consistency

The manifests are the source of truth. CI (and `make validate` locally) checks them via:

- `scripts/check_inventory_consistency.py` — manifests vs. filesystem
- `scripts/check_duplicate_prompt_ids.py` — duplicate IDs
- `scripts/validate_prompt_manifest.py`, `validate_skill_policy.py`, `validate_prompt_to_skill_map.py`, `validate_agents.py`, `validate_stage_manifest.py`
- `scripts/validate_frontmatter.py`, `lint_prompt_contracts.py`

If you rename a prompt, update `prompt_manifest.yaml`, `prompt_aliases.yaml`, `prompt_to_skill_map.yaml`, and regenerate `PROMPT_INDEX.md`.

## Claude Code plugin link

The plugin under [`../plugin/crafting-system/`](../plugin/crafting-system/) consumes a curated subset of these prompts as **skills** and **subagents**. The wiring lives in:

- [`skill_manifest.yaml`](skill_manifest.yaml) — skill definitions, paths, invocation policy
- [`agent_manifest.yaml`](agent_manifest.yaml) — subagent definitions, tools, mutation policy
- [`prompt_to_skill_map.yaml`](prompt_to_skill_map.yaml) — which prompt(s) back which skill

Local plugin test:

```bash
cd ..   # repo root
bash plugin/crafting-system/scripts/validate-plugin.sh
bash plugin/crafting-system/scripts/smoke-test.sh
claude --plugin-dir ./plugin/crafting-system
```


## Safety

Do not blindly copy every file in this directory into a target repository. The intended use is:

1. Pick a stage from [`PROMPT_INDEX.md`](PROMPT_INDEX.md).
2. Load the relevant prompt(s) into Claude/Claude Code/Cursor.
3. Generate **project-specific** files (CLAUDE.md, AGENTS.md, .cursor/rules, docs/, etc.) from the templates.

Never commit personal Claude/Cursor settings, secrets, local paths, chat logs, or assistant scratch artifacts to the target repository.
